# FRIDAY

FRIDAY 是一个以 Obsidian 为工作中心的本地 AI 工作流产品。

它把项目资料、任务拆解、知识沉淀、AI 协作和 Git 同步收进同一个可读的本地空间里，让非技术用户也能获得“过程可追踪、能力可沉淀、上下文可复用”的 AI 工作方式。

## FRIDAY 解决什么问题

很多 AI 工具能回答问题，但很难长期理解你的工作现场。

FRIDAY 要解决的是另一件事：把 AI 放进真实的工作流里，让它看得见你的项目资料、历史判断、当前任务和团队协作轨迹。

它重点降低三类摩擦：

- 不让业务用户为了用 AI 先学习 VSCode、Git 命令和复杂工程结构。
- 不让项目资料、沟通记录、草稿和 AI 输出散落在多个工具里。
- 不让 Prompt、Skills、知识沉淀和项目经验只停留在个人临时对话里。

## 适合谁

FRIDAY 适合需要长期维护项目知识、沉淀工作方法、并希望把 AI 放进日常工作流的人。

典型场景包括：

- 业务团队用 AI 辅助研究、写作、复盘和资料整理。
- 项目负责人希望让资料、决策、任务和同步状态集中在一个本地空间。
- 团队希望通过 Git 获得版本历史和协作能力，但不想让每个成员都学习 Git 操作。
- 个人希望让 AI 持续理解自己的项目，而不是每次对话都从零开始。

## 核心能力

- **Obsidian 工作中心**：用本地 Markdown 文件承载项目资料、草稿、任务和知识沉淀。
- **隐形 Git 同步**：Git 仍然负责版本历史和团队协作，但用户不需要面对 `add / commit / push`。
- **项目边界**：每个项目有明确的本地路径和同步状态，减少资料混乱和跨项目污染。
- **AI 对话工作台**：在 Daily Board 里围绕当前项目与 FRIDAY 协作，保留上下文和执行轨迹。
- **Skills 能力层**：用 Markdown 描述可复用工作方法，让能力可以沉淀和迭代。
- **Memory 与 Soul**：用长期事实和角色设定帮助 FRIDAY 保持稳定的协作姿态。
- **官方频道**：通过订阅栏目获得官方指南、更新日志和产品思考，内容更新不再强绑定插件版本。

## 第一次怎么开始

1. 在 Obsidian 里启用 FRIDAY 插件。
2. 到设置页完成基础配置，包括显示名称、Git 用户信息和访问凭据。
3. 在“项目”里注册一个本地项目，或绑定一个已有远端仓库。
4. 打开 Daily Board，选择当前项目，开始和 FRIDAY 对话。
5. 如果是第一次了解 FRIDAY，先阅读 `Start Here · 从这里开始` 里的入门内容。

## 当前边界

FRIDAY 仍在快速演进中。当前版本优先保证本地文件、项目边界、同步链路和官方内容订阅的稳定性。

需要注意：

- FRIDAY 不是替你做所有决策的自动代理，关键动作仍应由用户确认。
- Git 同步依赖本地 Git 环境、网络和远端仓库权限。
- AI 能力依赖你配置的大模型服务；模型不可用时，本地项目和基础同步能力仍应尽量保持可用。
- 官方频道内容采用订阅和镜像机制，适合阅读和复制引用，不建议直接在官方栏目内改写。
