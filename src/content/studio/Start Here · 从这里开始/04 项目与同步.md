# 04 项目与同步

项目是 FRIDAY 的工作边界。同步只是把项目内容和远端仓库保持一致的可选能力。

![[assets/04-01-sync-entry.png|520]]

## 项目先于同步

为了确保Agent在一个我们可控的范围内进行读取、写入操作，与 FRIDAY 开展对话前需要明确一个“项目”。我们为这个项目配置文件夹（类似IDE中的代码仓库），这决定了哪些文件 FRIDAY 可以读、哪些目录可以写、`@ 文件夹` 应该落在哪个范围里。

本地项目也可以正常对话。只有你想把项目推到远端仓库、从远端拉取，或在多台设备间保持一致时，才需要配置 Git 同步。

## 创建方式

创建项目有两种途径，一种是从Vault里选择一个文件夹，另一种是从远端仓库（码云，Gitee）拉取。前者，项目内有哪些文件由你在本地的这个文件夹里有什么决定，后者由远端仓库内有什么决定。

| 方式 | 说明 |
| --- | --- |
| 本地新建 | 适合从零开始建一个项目，可以先不配置远端 |
| 远端拉取 | 适合从远程仓库初始化项目，需要填写 Git 远程地址 |

如果目标目录已经是 Git 仓库，FRIDAY 会尝试识别远端地址。识别不到时，也可以先保存为本地项目，之后再补远程路径。

如果你的团队已经在远端仓库建立了团队知识库，可以使用远端拉取模式建立项目，填入仓库链接后，FRIDAY 会把远端仓库克隆到你选择的文件夹中。

注意，为了避免git仓库嵌套导致复杂的同步逻辑，如果你选择的文件夹的上层文件夹已经进行过git初始化，选择这个文件夹建立项目会报错。

## 选择工作范围

新建本地项目时，你需要先选择 Vault 里的一个文件夹。

常见选择：

| 选择 | 适合场景 |
| --- | --- |
| 已有文件夹 | 你已经有一组项目笔记 |
| `/（在 Vault 根目录下新建同名文件夹）` | 你还没有项目文件夹，希望 FRIDAY 帮你创建 |
| 整个 Vault | 高级选项，只在你明确想让项目边界覆盖整个 Vault 时使用 |

> [!warning]
> 将整个 Vault 作为项目会扩大读写边界。只有当你明确知道风险，并且希望 FRIDAY 可以处理整个 Vault 时再使用。


## 项目组

项目组只负责整理项目列表，不改变文件路径。你可以用它区分：

- 工作项目。
- 个人项目。
- 实验项目。
- 客户或团队项目。

项目组不会影响 FRIDAY 的读写边界，真正决定边界的是项目根目录。

## 当前项目

当前项目是 FRIDAY 执行任务时默认使用的项目。切换当前项目后，对话、同步状态、Wiki 编译和工具读写都会跟着切换。

如果 FRIDAY 读不到文件，或把任务理解成了另一个项目，先检查当前项目是否选对。

## 同步模式

FRIDAY 支持：

- 手动同步：你主动点击同步。
- 空闲自动同步：空闲一段时间后自动同步。
- 连续自动同步：持续监听变化并同步。

第一次接入项目时，建议先使用手动同步。确认远端、分支、忽略规则都正确后，再开启自动同步。

## 什么时候暂时不需要同步

这些情况可以先不配 Git：

- 你只是想试用对话。
- 项目只在当前 Vault 内使用。
- 还没确定目录结构。
- 远端仓库、分支和权限还没准备好。

## 冲突处理

同步冲突出现时，FRIDAY 会保留冲突快照，并提供：

- 保留本地。
- 保留远端。
- 查看快照。
- 生成修复建议。

> [!warning]
> 冲突处理前，先看清楚当前项目和冲突文件路径。不要只按按钮名判断，因为“本地”和“远端”代表的是两个不同版本的完整文件。
