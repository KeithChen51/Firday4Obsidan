# Changelog

这里记录 F.R.I.D.A.Y 面向用户的版本变化，按版本倒序排列。

## 0.2.8
发布日期：2026-04-22

- `F.R.I.D.A.Y/` 现在被重新定义为官方频道在本地 vault 里的挂载点；它的一级目录和一级 Markdown 文件会作为可订阅栏目呈现，而不再承载插件配置、运行时状态或脚手架内容。
- 官方内容更新与插件版本更新正式解耦：构建流程会生成独立的 `release/official-content/*` feed，插件更新继续只发布插件产物，官方栏目目录和正文通过独立内容 feed 刷新。
- 设置页移除了原先面向 slash commands 的用户入口，并在相同导航槽位换成“订阅频道 / Subscriptions”；第一版只接入“官方频道”，但信息架构已经为后续社区来源预留。
- 官方栏目改为从远端 feed 元数据动态发现，新出现的栏目默认不会自动订阅，只会进入可订阅列表，避免在用户未确认前直接落盘到 `F.R.I.D.A.Y/`。
- `LegacyFridayRootMigrationService` 现在承担 `F.R.I.D.A.Y/` 接管前的长期安全门：如果根目录下仍有历史 `项目` / `个人` / `Agents` / `runtime` / `_配置.md` 或其他未知内容，catalog 仍可刷新，但 destructive apply 会被阻断，直到用户迁移、清理或显式确认接管。
- 清理 F.R.I.D.A.Y 根目录的可见运行时痕迹：工具审计、步骤追踪和设置镜像迁移到隐藏本地状态目录，插件启动时不再继续在 vault 里铺开 `F.R.I.D.A.Y/runtime`、可见配置镜像等系统文件。
- 项目设置页新增“遗留 Friday 根目录内容”面板，可以盘点旧 `项目` / `个人` / `Agents` 目录，导入仍可识别为项目的旧文件夹，并只对安全的空目录和过时镜像执行清理，降低历史 vault 升级后的手工整理成本。
- 项目边界判定与注册流程进一步收紧：当前文件归属、成员数据与同步入口统一改为基于已注册 `boundaryPath` 判断；本地/远端注册时不再偷偷推导目标目录，必须明确选择 Obsidian 路径，减少项目嵌套和误写入。
- 工作台身份展示继续收口：顶部标题栏只保留 `F.R.I.D.A.Y` 字标，用户消息优先显示基础配置里的“显示名称”，不再固定显示“你”或头像角标；基础配置也同步移除了旧的用户 ID 输入项。
- `F.R.I.D.A.Y` 字标调整回 n-neco 风格字体，并保持只作用于工作台品牌、聊天消息角色名和设置标题等指定位置，不会扩散到普通正文文本。

## 0.2.7
发布日期：2026-04-21

- Soul 现在成为唯一的运行时身份入口：设置模型、当前角色切换、Daily Board 对话工作台和插件 API 全部改为直接读取 `SoulStore`，旧的 `settings.agents`、`activeAgentId` 与 `getActiveAgent` / `createAgent` 兼容接口已从主链路移除。
- 旧 Agent 数据迁移进一步收口：启动时会把历史 Agent 档案导入为 Soul 定义，并同步迁移旧会话、工具批准规则和模型偏好；日常会话与快照存储不再依赖 `AgentService` 的 legacy 路径。
- `来自制作组` 栏目完成命名更新：`幕后笔记 · Behind the Build` 统一为 `Study with F.R.I.D.A.Y`，`迭代手记 · Changelog` 简化为 `Changelog`，同时保留旧路径兼容，避免已有 vault 升级后断链。
- 调整初始化命令的全局 `FRIDAY.md` 写入路径，并补齐 Soul-only 与 studio 路径迁移相关的回归测试，降低后续迭代时的兼容性回退风险。

## 0.2.6
发布日期：2026-04-20

- F.R.I.D.A.Y 运行时回归单代理执行模型，`subagent` 已从工具清单、设置项、运行时提示和活动视图中移除，行为边界更直接也更可解释。
- 新增长期记忆工具 `memory`，现在可以显式执行 `add`、`replace`、`remove`，把真正需要跨轮保留的信息写入全局或当前项目记忆。
- 长期记忆统一收口为两层 source of truth：全局记忆固定写入 `F.R.I.D.A.Y/_runtime/memory/global.md`，项目记忆固定写入 `<projectRoot>/.friday/memory/project.md`。
- 记忆写入现在遵循“下一轮可见”规则，当前回合的上下文快照不会被隐式改写，减少回答过程中的状态漂移。
- 移除旧的自动记忆提取链路和 `maintain-memory` 特殊路径，长期记忆不再偷偷抽取或分散落盘，排查和维护都更简单。
- 补齐 memory v1 与 subagent 下线的回归测试，覆盖工具清单、提示协议、事件路由、路径约定和容量限制等关键合同。

## 0.2.5
发布日期：2026-04-19

- 修复自动更新卡片的主操作流，当前版本号右侧按钮现在会在“检查更新”和强调色“应用更新”之间原位切换，不再分散到多个入口。
- 修复自动更新区域的重复操作，移除了单独的“更新操作”和“忽略当前版本”，减少状态分叉和误操作。
- 修复启动检查与手动更新互相耦合的问题，现在“启动时自动检查”只负责自动检查新版本，不再依赖单独的总开关。
- 修复内部更新后的收尾体验，应用更新成功后会直接提供“立即重启 Obsidian”按钮，便于一键重载生效。
- 修复项目组创建时中文名称会被误判为 ID 非法的问题，现在支持用中文和中英混合名称生成可用的项目组 ID。
- 修复基础配置中的 Git 用户名、Git 邮箱和 Git 令牌输入框在首次输入字符时丢失焦点的问题，连续录入更稳定。
- 将内置技能的正文改为按技能目录维护的 `SKILL.md` 源文件，统一通过生成脚本构建到插件产物中，后续维护和升级同步更稳定。
- 优化 `obsidian-cli` 内置技能说明，补充 Windows 下的 `where obsidian`、`obsidian version`、`obsidian eval` 预检流程，并明确 `Obsidian.com`、安装器版本和 `PATH` 的排查方式。
- 重写 `obsidian-markdown`、`json-canvas`、`obsidian-bases` 这 3 个 Obsidian 内置技能的内容规则，补齐过度约束、规范错误和真实编辑护栏。
- 为内置技能增加回归校验，确保 `builtin://.../SKILL.md` 虚拟路径始终映射到最新的源码内容，减少文案与实际插件产物不一致的问题。
- 技能管理页现在会在有过修订的 Obsidian 内置 skill 名称旁显示注释图标，悬浮或点击即可查看“原版是什么 / 为什么不好 / 改成了什么”的说明浮层。
- 新增 `来自制作组` 栏目，统一整理 `迭代手记`、`幕后笔记`、`从这里开始` 三类内容，并将插件内部更新日志同步路径调整到 `F.R.I.D.A.Y/来自制作组/迭代手记 · Changelog.md`。
- 新增 `src/content/studio` 作为 `来自制作组` 的源码内容目录，`README`、`从这里开始` 与 `幕后笔记` 会在构建时编译进插件，并在用户更新后随启动同步到 vault。
- 统一对话页和设置页的模型选择体验，对话页中的模型下拉现在会直接修改当前 Agent 的模型配置，不再额外引入一层“跟随默认”的临时逻辑。
- 统一对话页和设置页的权限模式体验，对话页中的权限选择会直接写回当前工具权限设置，减少会话级和全局级状态分叉。
- 修复工作进行中聊天输入被整体锁死的问题，现在可以提前输入下一条指令并加入队列，当前任务完成后会自动继续执行，发送按钮也不再长时间误显示为“发送中”。
- 优化斜杠命令的技能候选渲染，`/skill xxx` 在下拉列表中现在会显示为“技能：xxx”，降低命令提示的理解成本。
