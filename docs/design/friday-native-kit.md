# FRIDAY Obsidian Native Kit v0.2

这份文档是 FRIDAY Obsidian 插件 UI 的 Native Kit 规范源。
它不是独立设计稿，也不是一次性静态页面，而是把已确认的组件候选沉淀成后续代码可以执行的 UI 合约。

- 品牌素材：`brand/`

## 设计原则

FRIDAY 的插件界面应该先像 Obsidian 原生界面，再在必要位置出现 FRIDAY 的身份。

换句话说：

- Obsidian 负责基础控件、密度、主题适配和普通工作流。
- FRIDAY 负责身份识别、助手角色、执行状态、审批状态和产物语义。
- 品牌视觉只在能帮助用户判断“谁在行动、当前处于什么状态、下一步要做什么”时出现。

## 三层结构

### Obsidian 原生层

用于普通设置、按钮、输入、列表、菜单、选择器和弹窗。

要求：

- 优先使用 Obsidian 原生组件或现有 `SettingsKit` 能力。
- 使用 Obsidian CSS 变量，不硬编码主题色。
- 控件密度与 Obsidian 保持一致。
- 普通操作不要额外品牌化。

### FRIDAY 身份层

用于需要明确 FRIDAY 身份的入口和状态。

适用位置：

- 插件入口
- 文档或 onboarding 页头
- 工作台顶部栏
- 助手输出身份
- 空状态
- 审批或执行中需要标明行动者的区域

要求：

- 品牌 logo 和 `FRIDAY` 字样只在身份位置出现。
- 不要把 logo 放进每个普通组件。
- 不要用大面积品牌色覆盖 Obsidian 主题。

### Agent 信息层

用于表达助手输出、工具调用、Task Bar、审批、执行过程和产物。

要求：

- 助手、执行过程和 Task Bar 使用同一套信息语法。
- 工具调用是低强调运行记录，不是大卡片。
- 产物需要能区分文件类型。
- 审批是强提醒，但应占用对话输入区，而不是散落成多个独立卡片。

## 主题与样式变量

Kit 组件必须跟随 Obsidian 主题变化。

优先使用：

- `var(--background-primary)`
- `var(--background-secondary)`
- `var(--background-primary-alt)`
- `var(--text-normal)`
- `var(--text-muted)`
- `var(--text-faint)`
- `var(--background-modifier-border)`
- `var(--interactive-accent)`
- Obsidian 语义色变量
- `color-mix()` 生成轻量选中、悬停、运行中背景

避免：

- 写死浅色或深色背景。
- 大面积品牌色背景。
- 装饰性渐变、发光、玻璃拟态。
- 只在默认主题下成立的对比度。

## 密度与形状

FRIDAY 是工作型插件，不是营销页。

规则：

- 普通控件圆角：6 到 8 px。
- 分组面板圆角：8 到 12 px。
- 状态标签可以使用胶囊圆角。
- 不要把卡片再放进装饰性卡片里。
- 大块信息区应该保持扫描效率，不要做成松散 dashboard。

建议间距：

| 间距 | 用途 |
| ---: | --- |
| 4 px | 图标与文字、紧凑标签 |
| 8 px | 控件之间 |
| 12 px | 小分组之间 |
| 16 px | 面板内边距 |
| 24 px | 大段落或大组件之间 |

## 动画

Native Kit 可以定义 UI 动画，但动画必须服务于状态理解。

动画 token：

| 名称 | 时长 | 用途 |
| --- | --- | --- |
| `fast` | 100 到 140 ms | hover、press、focus、选中 |
| `normal` | 160 到 240 ms | 面板展开、输入状态切换、菜单出现 |
| `slow` | 1200 到 1800 ms | 执行中缓慢闪烁、进度条呼吸 |

规则：

- 必须尊重 `prefers-reduced-motion`。
- 优先动 opacity、transform、background position。
- 正在执行可以使用低幅度渐变或进度条。
- 审批等待不要闪烁，保持强提醒但静止。
- 不要让大块内容持续动，避免干扰阅读。

## 组件规范

### 品牌页头

用途：

- Native Kit 文档
- onboarding
- 发布说明
- 明确品牌入口

规则：

- 使用横向 FRIDAY wordmark。
- 尺寸克制，不做页面主视觉。
- 普通插件面板不重复使用品牌页头。

### 小尺寸标识

用途：

- 助手身份
- 状态头像
- 小尺寸品牌入口

规则：

- 使用 Double Shell mark。
- 跟随主题适配。
- 可用单色或轻量强调色，不使用大色块。

### 插件入口图标

用途：

- 插件市场
- 仓库封面
- 外部入口预览

规则：

- 使用 `brand/` 中已有图标资产。
- 不把市场图标样式搬进普通 Obsidian 面板。

### 设置页框架

结构：

1. 标题区。
2. 分区切换或紧凑 tabs。
3. 原生设置组。
4. 原生设置行。
5. 危险操作放在组尾。

规则：

- 优先使用 Obsidian `Setting`。
- 优先复用 `src/ui/obsidian-native/SettingsKit.ts`。
- 设置页可以出现一次小的 FRIDAY 身份，不要每个设置组都品牌化。

### 设置行状态

用途：

- 设置项旁边的成功、同步、待配置、失败状态。

规则：

- 普通状态使用 muted 文本。
- 需要注意时才使用语义色。
- 不要把小状态做成单独提醒卡片。

### 危险操作设置行

用途：

- 删除、重置、断开连接等不可逆操作。

规则：

- 放在设置组末尾。
- 在按钮前解释后果。
- 不可逆操作需要二次确认。
- 使用 Obsidian 原生 destructive 语义。

### 空状态

用途：

- 尚无项目、文件、任务、记录。

规则：

- 可以出现一个小 FRIDAY mark。
- 说明缺少什么，以及下一步做什么。
- 只提供一个主操作。
- 文案要实用，不做宣传。

### 行内提醒

用途：

- 局部警告。
- 阻塞状态。
- 可恢复错误。
- 前置条件缺失。

规则：

- 风格要贴近 Obsidian 原生 callout。
- 不要像营销 banner。
- 有恢复动作时直接给出动作。
- 严重程度使用 Obsidian 语义色，不使用品牌色。

### 前置条件列表

用途：

- 展示工作流开始前需要满足的权限、文件、配置或连接状态。

规则：

- 每个条件是一行。
- 明确区分已完成、待完成、阻塞。
- 行动词要短：连接、选择、刷新、重试。

### 审批强提醒

用途：

- 当 FRIDAY 需要用户确认后才能继续执行。

规则：

- 使用 `friday-approval-card` 作为统一审批样式。
- 当审批阻塞对话时，审批卡片占用对话输入区。
- 不再额外保留一个独立的“审批卡片”组件。
- 文案说明：等待什么、确认后会发生什么。
- 主按钮是明确继续动作，例如“应用修改”。
- 次按钮保留但视觉弱一些，例如“不应用”。
- 审批状态不做呼吸或闪烁动画。

### 工作台顶部栏

用途：

- Daily Board
- 项目页
- 工具页

结构：

- 左侧：品牌 logo + `FRIDAY`。
- 中间或右侧：当前项目选择器。
- 右侧：搜索、刷新、设置等原生操作。

规则：

- 左侧品牌 logo 要保留。
- 品牌位显示 `FRIDAY`，不显示多余 slogan。
- 常见工具操作用图标或原生按钮。
- 不使用不好看的孤立 icon 容器。

### 助手消息

结构：

- 用户消息：右侧对话气泡。
- FRIDAY 消息：文档流，不做 FRIDAY 对话气泡。
- FRIDAY 身份：每组输出出现一次。
- 输出内容：按类型分正文、工具调用、产物。

输出类型：

| 类型 | 展示方式 |
| --- | --- |
| 正文 | 普通文档流正文 |
| 工具调用 | 低强调 icon + 工具名 + 操作内容 |
| 产物 | 文件行，按文件类型显示 icon |

规则：

- 工具调用不要做成重卡片。
- 工具调用不承担主要阅读内容，只是运行记录。
- 不再单独定义一个高强调“执行计划”样式；计划状态由 Task Bar 和执行过程承接。

### 对话输入区

用途：

- 助手输入框。
- 模型、权限、`@`、Skill 控制。
- Skill 列表。
- `@` 文件引用选择。
- Task Bar 组合态。
- 审批占用态。

基础结构：

- 输入内容区。
- 控制行：模型、权限、`@`、`+Skill`、发送。
- 附着区：Task Bar、Skill 列表、`@` 文件选择、审批强提醒。

状态：

- 未输入。
- 已输入普通文本。
- 调用 Skill。
- Skill 列表向输入框上方展开。
- `@` 文件选择向输入框上方展开。
- Task Bar 收起并贴住输入框。
- Task Bar 展开并保留输入框在下方。
- 审批强提醒占用输入区。

规则：

- 去掉输入框下方的小上下文状态条。
- 模型、权限、`@`、`+Skill` 按钮仍保留在控制行。
- Skill 被选中后只显示技能名，不显示前导 `/`。
- Skill 列表项只显示技能名，不显示 `Skill` 前缀。
- 实际命令输入可以仍然使用 `/skills` 触发。
- `@` 文件选择列表可以用文件类型 icon 区分 `.md`、`.canvas`、`.html` 等。
- 已选中的 `@` token 不需要文件类型 icon。

### Task Bar

用途：

- FRIDAY 已经规划分步执行，并需要让用户看到当前执行进度。

收起态：

- 默认贴住输入框上方。
- 与输入框共享一个视觉外壳。
- 显示当前状态、步骤数、任务名、耗时、展开入口。

展开态：

- 在输入框上方展开。
- 显示已完成、正在执行、未开始的后续步骤。
- 输入框仍在 Task Bar 下方。

规则：

- 正在执行步骤用整体背景弱强调。
- 不把每一步做成大卡片。
- 不占用输入内容区。
- 展开后不能只显示已完成和进行中步骤，后续未开始步骤也要出现。

### 执行过程时间线

用途：

- 展示更完整的执行历史、工具记录和产物。

规则：

- 与助手消息中的工具调用共用同一套事件语言。
- 工具事件保持轻量。
- 产物用文件类型 icon 区分。
- 至少区分 Markdown 文件、Canvas/白板文件、普通笔记或文档。
- 不重复展示 Task Bar 已经表达的当前摘要。

### 项目状态组

状态：暂缓。

已知方向：

- B 版本的紧凑方向相对可取。
- 仍需要重新梳理项目焦点、风险、状态和行动层级。
- 不应该做成重 dashboard。

规则：

- 首批迁移不改项目状态组。
- 不从项目状态组中抽公共组件，避免把未定样式固化进 Kit。

## 首批实现范围

可以进入首批代码迁移：

- 工作台顶部栏
- 助手消息
- 对话输入区
- Task Bar
- 审批强提醒
- 执行过程时间线
- 已经接近 Native Kit 的设置组件

不进入首批迁移：

- 项目状态组
- 与以上组件无关的大范围视觉重构
- 普通设置行的品牌化改造

## 验收清单

迁移任何组件前，需要逐项检查：

- [ ] 能映射到本文中的一个组件规范。
- [ ] surface、文字、边框、状态色都使用 Obsidian 主题变量。
- [ ] FRIDAY 品牌只出现在规范允许的位置。
- [ ] 组件密度适合反复使用，不像营销卡片。
- [ ] 没有无意义的卡片套卡片。
- [ ] 明暗主题都可读。
- [ ] 动画遵守 `prefers-reduced-motion`。
- [ ] 有回归测试或明确的手动验证路径。
- [ ] 未改动 `项目状态组`，除非暂缓状态被明确解除。
