# FRIDAY Obsidian Native Kit v0.2

这份文档是 FRIDAY Obsidian 插件 UI 的 Native Kit 规范源。
它不是独立设计稿，也不是一次性静态页面，而是把已确认的组件候选沉淀成后续代码可以执行的 UI 合约。

## 设计原则

FRIDAY 的插件界面应该先像 Obsidian 原生界面，再在必要位置出现 FRIDAY 的身份。

换句话说：

- Obsidian 负责基础控件、密度、主题适配和普通工作流。
- FRIDAY 负责身份识别、助手角色、执行状态、审批状态和产物语义。
- 品牌视觉只在能帮助用户判断“谁在行动、当前处于什么状态、下一步要做什么”时出现。

## 三层结构

### Obsidian 原生层

用于普通设置、按钮、输入、列表、菜单、选择器和弹窗。

要求：

- 优先使用 Obsidian 原生组件或现有 `SettingsKit` 能力。
- 使用 Obsidian CSS 变量，不硬编码主题色。
- 控件密度与 Obsidian 保持一致。
- 普通操作不要额外品牌化。

### FRIDAY 身份层

用于需要明确 FRIDAY 身份的入口和状态。

适用位置：

- 插件入口
- 文档或 onboarding 页头
- 工作台顶部栏
- 助手输出身份
- 空状态
- 审批或执行中需要标明行动者的区域

要求：

- 品牌 logo 和 `FRIDAY` 字样只在身份位置出现。
- 不要把 logo 放进每个普通组件。
- 不要用大面积品牌色覆盖 Obsidian 主题。

### Agent 信息层

用于表达助手输出、工具调用、Task Bar、审批、助手过程展开和产物。

要求：

- 助手消息内的过程态、结果态和 Task Bar 使用同一套信息语法。
- 工具调用是低强调运行记录，不是大卡片。
- 产物需要能区分文件类型。
- 审批是强提醒，但应占用对话输入区，而不是散落成多个独立卡片。

## 主题与样式变量

Kit 组件必须跟随 Obsidian 主题变化。

优先使用：

- `var(--background-primary)`
- `var(--background-secondary)`
- `var(--background-primary-alt)`
- `var(--text-normal)`
- `var(--text-muted)`
- `var(--text-faint)`
- `var(--background-modifier-border)`
- `var(--interactive-accent)`
- Obsidian 语义色变量
- `color-mix()` 生成轻量选中、悬停、运行中背景

避免：

- 写死浅色或深色背景。
- 大面积品牌色背景。
- 装饰性渐变、发光、玻璃拟态。
- 只在默认主题下成立的对比度。

## 密度与形状

FRIDAY 是工作型插件，不是营销页。

规则：

- 普通控件圆角：6 到 8 px。
- 分组面板圆角：8 到 12 px。
- 状态标签可以使用胶囊圆角。
- 不要把卡片再放进装饰性卡片里。
- 大块信息区应该保持扫描效率，不要做成松散 dashboard。

建议间距：

| 间距 | 用途 |
| ---: | --- |
| 4 px | 图标与文字、紧凑标签 |
| 8 px | 控件之间 |
| 12 px | 小分组之间 |
| 16 px | 面板内边距 |
| 24 px | 大段落或大组件之间 |

## 动画

Native Kit 可以定义 UI 动画，但动画必须服务于状态理解。

动画 token：

| 名称 | 时长 | 用途 |
| --- | --- | --- |
| `fast` | 100 到 140 ms | hover、press、focus、选中 |
| `normal` | 160 到 240 ms | 面板展开、输入状态切换、菜单出现 |
| `slow` | 1200 到 1800 ms | 执行中缓慢闪烁、进度条呼吸 |

规则：

- 必须尊重 `prefers-reduced-motion`。
- 优先动 opacity、transform、background position。
- 正在执行可以使用低幅度渐变或进度条。
- 运行中表面可用纯 CSS 背景扫光；当前插件 `styles.css` 已有 `@keyframes` 和 `prefers-reduced-motion` 用法，Obsidian 插件 DOM 中可以落地。
- 审批等待不要闪烁，保持强提醒但静止。
- 不要让大块内容持续动，避免干扰阅读。

## 组件规范

### 跨组件元组件

用途：

- 给多个 Kit 组件共享同一套底层视觉语法。
- 避免状态、文件行、浮层、工具记录和控制按钮在不同页面重复发明。

当前元组件：

| 元组件 | 复用位置 |
| --- | --- |
| 状态徽标 | 设置行、Task Bar、同步、审批、会话列表 |
| 文件类型图标元件 | 产物、`@` 文件选择、Diff、同步冲突 |
| 低强调事件行 | 工具调用、后台记录、助手过程展开、同步日志 |
| 运行中表面 | 当前步骤、刷新进度、后台 Agent、长任务 |
| 浮层列表项 | Skill、`@` 文件、会话菜单、项目选择器 |
| 控制按钮组 | 模型、权限、`@`、`+Skill`、搜索、刷新、设置 |

规则：

- 元组件不直接表达业务含义，只提供稳定的密度、布局和状态语法。
- 元组件必须使用 Obsidian 主题变量，不带页面级品牌装饰。
- 业务组件优先组合元组件，只有语义确实不同才新增专属样式。
- 文件类型图标只在需要区分文件类型时使用；普通会话行和已选 token 不做差异化图标。
- 后续大组件不得重新定义本层已有的状态徽标、文件类型图标、工具 icon、浮层列表项、运行中表面或控制按钮；HTML 画板用静态测试防止旧局部 class 回流。

### 品牌页头

用途：

- Native Kit 文档
- onboarding
- 发布说明
- 明确品牌入口

规则：

- 使用横向 FRIDAY wordmark。
- 尺寸克制，不做页面主视觉。
- 普通插件面板不重复使用品牌页头。

### 小尺寸标识

用途：

- 助手身份
- 状态头像
- 小尺寸品牌入口

规则：

- 使用 Double Shell mark。
- 跟随主题适配。
- 可用单色或轻量强调色，不使用大色块。

### 插件入口图标

用途：

- 插件市场
- 仓库封面
- 外部入口预览

规则：

- 使用 `brand/` 中已有图标资产。
- 不把市场图标样式搬进普通 Obsidian 面板。

### 设置页框架

结构：

1. 标题区。
2. 分区切换或紧凑 tabs。
3. 原生设置组。
4. 原生设置行。
5. 危险操作放在组尾。

规则：

- 优先使用 Obsidian `Setting`。
- 优先复用 `src/ui/obsidian-native/SettingsKit.ts`。
- 设置页可以出现一次小的 FRIDAY 身份，不要每个设置组都品牌化。

### 设置行状态

用途：

- 设置项旁边的成功、同步、待配置、失败状态。

规则：

- 普通状态使用 muted 文本。
- 需要注意时才使用语义色。
- 不要把小状态做成单独提醒卡片。

### 危险操作设置行

用途：

- 删除、重置、断开连接等不可逆操作。

规则：

- 放在设置组末尾。
- 在按钮前解释后果。
- 不可逆操作需要二次确认。
- 使用 Obsidian 原生 destructive 语义。

### 设置页状态反馈

用途：

- LLM 连接状态。
- 错误详情。
- 刷新进度。
- 路径或配置风险提示。

规则：

- 先复用设置行状态、状态徽标和行内提醒。
- 状态反馈应贴着相关设置组出现，不要散落成独立 dashboard。
- 进度条只用于后台刷新或同步，不用于静态状态。
- 错误详情可以展开，但默认不占据大量垂直空间。

### 空状态

用途：

- 尚无项目、文件、任务、记录。

规则：

- 可以出现一个小 FRIDAY mark。
- 说明缺少什么，以及下一步做什么。
- 只提供一个主操作。
- 文案要实用，不做宣传。

### 行内提醒

用途：

- 局部警告。
- 阻塞状态。
- 可恢复错误。
- 前置条件缺失。

规则：

- 风格要贴近 Obsidian 原生 callout。
- 不要像营销 banner。
- 有恢复动作时直接给出动作。
- 严重程度使用 Obsidian 语义色，不使用品牌色。

### 前置条件列表

用途：

- 展示工作流开始前需要满足的权限、文件、配置或连接状态。

规则：

- 每个条件是一行。
- 明确区分已完成、待完成、阻塞。
- 行动词要短：连接、选择、刷新、重试。

### 审批强提醒

用途：

- 当 FRIDAY 需要用户确认后才能继续执行。

规则：

- 使用 `friday-approval-card` 作为统一审批样式。
- 当审批阻塞对话时，审批卡片占用对话输入区。
- 不再额外保留一个独立的“审批卡片”组件。
- 文案说明：等待什么、确认后会发生什么。
- 主按钮是明确继续动作，例如“应用修改”。
- 次按钮保留但视觉弱一些，例如“不应用”。
- 审批状态不做呼吸或闪烁动画。

### 变更审阅 Diff

用途：

- 展示 FRIDAY 准备应用的文件修改。
- 帮助用户在审批前判断文件、范围和风险。

规则：

- 变更审阅是审批强提醒的子系统，不另起一套强提醒样式。
- 文件行使用文件类型图标元件。
- Diff 预览保持原生代码密度，增加、删除、普通行使用语义色弱区分。
- 完整 Diff 可以展开，但默认只展示足够判断风险的摘要。
- 操作按钮复用审批动作规则，例如“应用修改”“不应用”“查看完整 Diff”。

### 工作台顶部栏

用途：

- Daily Board
- 项目页
- 工具页

结构：

- 左侧：品牌 logo + `FRIDAY`。
- 中间或右侧：当前项目选择器。
- 右侧：搜索、刷新、设置等原生操作。

规则：

- 左侧品牌 logo 要保留。
- 品牌位显示 `FRIDAY`，不显示多余 slogan。
- 常见工具操作用图标或原生按钮。
- 不使用不好看的孤立 icon 容器。

### 首次引导步骤

用途：

- 项目注册。
- 模型配置。
- 权限或技能准备。

规则：

- 首次引导是配置缺口列表，不是欢迎页或营销页。
- 每一步只说明缺什么、为什么需要、下一步动作。
- 已完成步骤可保留弱状态，当前阻塞步骤给出主操作。
- 步骤右侧动作位使用同一尺寸和同一圆角，不混用按钮、胶囊和普通文本。
- 可出现一次 FRIDAY 身份，但不要重复品牌化每个步骤。

### 运行状态提示组

用途：

- 后台 Agent 状态。
- 输入排队提示。
- 临时上下文覆盖条。
- 长任务刷新或同步进度。

规则：

- 运行中状态复用运行中表面元组件。
- 运行中表面不放前置 icon，靠整体背景和弱动效表达进行中。
- 运行中表面与低强调事件行保持同一行高，并压缩到一行文字的信息条密度；主内容单行显示，宽度不足时省略状态说明，不换行撑高容器。
- 提示条应贴近触发位置，例如输入区、顶部栏或设置组。
- 输入排队不占用输入内容区，只提示当前任务结束后会继续。
- 临时覆盖条必须提供清除或查看入口。

### 能力控制中心

用途：

- 工具启用/禁用。
- 高风险工具权限。
- Skill 分组和审阅说明。

规则：

- 它是能力管理面板，不是普通设置组。
- Skill 名称直接显示技能名，不显示 `Skill` 前缀。
- 工具行统一使用行动类 icon；Skill 行统一使用技能/组件类 icon，不按具体工具或技能做差异化。
- 高风险能力要显示短解释和明确状态。
- 审阅说明使用轻量浮层，不把说明文案塞进每一行。

### 助手消息

结构：

- 用户消息：右侧对话气泡。
- FRIDAY 消息：文档流，不做 FRIDAY 对话气泡。
- FRIDAY 身份：每组输出出现一次。
- 输出内容：按类型分正文、工具调用、产物。

状态：

- 刚收到任务、搭建上下文和判断任务复杂度时，不展开过程，只显示 `[FRIDAY 小图标] FRIDAY 正在思考 8s`。
- 确认是复杂任务并进入显性过程态后，显示 `[FRIDAY 小图标] FRIDAY 正在工作 8s`，下方自然展开过程内容。
- 简单回答结果态显示 `[FRIDAY 小图标] FRIDAY 已思考 8s`，不显示过程内容。
- 复杂任务结果态显示 `[FRIDAY 小图标] FRIDAY 已完成工作 8s >`，保留用时信息；过程默认收起，可从 `FRIDAY` 名称或右侧小箭头展开。
- 显性过程态和复杂结果展开态中的每个过程步骤都可以点击展开，展开后只显示该步骤对应的具体工具调用过程。
- 已完成的过程步骤可以带一行低强调自然语言叙述，用来说明刚刚做了什么、发现了什么、接下来会怎么推进；正在执行且结果未返回的步骤不显示这类叙述。

输出类型：

| 类型 | 展示方式 |
| --- | --- |
| 正文 | 普通文档流正文 |
| 过程叙述 | 已完成步骤下方的一行低强调说明；展开步骤时，工具调用细节在叙述上方 |
| 工具调用 | 低强调 icon + 工具名 + 操作内容 |
| 产物 | 文件行，按文件类型显示 icon |

规则：

- 工具调用不要做成重卡片。
- 工具调用不承担主要阅读内容，只是运行记录。
- 过程展开里不要再加“过程”标题；FRIDAY 身份行和箭头已经承担入口说明。
- 过程步骤默认保持一行事件密度，长内容省略；工具调用细节只在步骤展开后出现。
- 过程叙述不单独成卡片，不使用强背景；它是步骤执行后的阶段性结论，文案优先使用“已做 / 发现 / 接下来”的自然句式。
- 过程步骤展开后的顺序是：步骤行 -> 工具调用细节 -> 过程叙述。收起时只隐藏工具调用细节，过程叙述仍显示在已完成步骤下方。
- 工具调用细节是过程步骤的子层级，视觉强度必须低于上层步骤：更矮、更淡、更少边框，不抢正在执行的主信息。
- 不再单独定义一个高强调“执行计划”样式；计划状态由 Task Bar 和助手消息里的过程展开承接。
- 不单独定义“执行过程时间线”组件；复杂任务过程属于助手消息的过程态或结果态展开内容。

### 对话输入区

用途：

- 助手输入框。
- 模型、权限、`@`、Skill 控制。
- Skill 列表。
- `@` 文件引用选择。
- Task Bar 组合态。
- 审批占用态。

基础结构：

- 输入内容区。
- 控制行：模型、权限、`@`、`+Skill`、发送。
- 附着区：Task Bar、Skill 列表、`@` 文件选择、审批强提醒。

状态：

- 未输入。
- 已输入普通文本。
- 调用 Skill。
- Skill 列表向输入框上方展开。
- `@` 文件选择向输入框上方展开。
- Task Bar 收起并贴住输入框。
- Task Bar 展开并保留输入框在下方。
- 审批强提醒占用输入区。

规则：

- 去掉输入框下方的小上下文状态条。
- 模型、权限、`@`、`+Skill` 按钮仍保留在控制行。
- Skill 被选中后只显示技能名，不显示前导 `/`。
- Skill 列表项只显示技能名，不显示 `Skill` 前缀。
- 实际命令输入可以仍然使用 `/skills` 触发。
- `@` 文件选择列表可以用文件类型 icon 区分 `.md`、`.canvas`、`.html` 等。
- 已选中的 `@` token 不需要文件类型 icon。

### 对话记录抽屉

用途：

- 搜索、分组和管理历史会话。
- 批量选择、重命名、菜单操作和空搜索状态。

规则：

- 抽屉是管理工具，不使用大渐变或强品牌装饰。
- 会话行复用低强调列表结构，当前会话用弱选中背景；暂不为每条会话做差异化 icon。
- 空状态复用空状态组件，只给一个恢复动作。
- 搜索、批量操作和更多菜单使用控制按钮组。

### Task Bar

用途：

- FRIDAY 已经规划分步执行，并需要让用户看到当前执行进度。

收起态：

- 默认贴住输入框上方。
- 与输入框共享一个视觉外壳。
- 显示当前状态、步骤数、任务名、耗时、展开入口。

展开态：

- 在输入框上方展开。
- 显示已完成、正在执行、未开始的后续步骤。
- 输入框仍在 Task Bar 下方。

规则：

- 正在执行步骤用整体背景弱强调。
- 不把每一步做成大卡片。
- 不占用输入内容区。
- 展开后不能只显示已完成和进行中步骤，后续未开始步骤也要出现。

### 同步冲突差异

用途：

- 展示本地和远端文件差异。
- 让用户确认采用本地、采用远端或继续查看。

规则：

- 同步冲突不等于项目状态组，可以先独立定义。
- 文件行使用文件类型图标元件。
- 双栏差异只用于来源对比；普通变更审阅继续使用变更审阅 Diff。
- 操作文案必须说明采用哪一侧，不使用模糊的“处理”。

### 项目状态组

状态：暂缓。

已知方向：

- B 版本的紧凑方向相对可取。
- 仍需要重新梳理项目焦点、风险、状态和行动层级。
- 不应该做成重 dashboard。

规则：

- 首批迁移不改项目状态组。
- 不从项目状态组中抽公共组件，避免把未定样式固化进 Kit。

## 验收清单

- [ ] 明暗主题都可读。
