产品定位
FRIDAY Desktop 是本地优先的工作台

面向组织和团队里的泛文档工作者，不把产品表达成 Coding Agent。

形态原则
桌面端是新形态，但不偏离 FRIDAY 既有能力

交互可以脱离 Obsidian 重新组织；能力侧优先复用 runtime、过程面板、资料、Skill、Soul、同步和本地状态。

v0 清单
第一版只做本地桌面工作闭环

项目主页、对话页、项目资料库、产物画布、权限模式、Reference / Trace、Skill / Soul 基础入口、归档恢复进入 v0；Wiki、团队、日历、模块市场和高级 Soul 暂缓。

视觉基准
Codex 只参考信息结构，视觉回到 FRIDAY VI

不是机械套色，而是遵守柔和墨色、Warm Bone 文档底色、少量 Muted Teal 功能色、少阴影和低侵入排版。

产物画布
默认一个当前产物，顶部标签切换

需要并行查看时，用户拖拽标签把产物拆成左右或上下并列显示。

产物区
产物区是当前对话已有产物列表

它只在进入对话后出现；资源入口是一排放在对话标题行右侧的 icon，点击后在下方共用资源窗口中切换资料库、文件树、技能和产物，不作为项目主页里的一级文件管理模块。

资源默认
有产物默认产物，无产物默认资料库

当前对话资源窗口按对话记住用户上次选择；没有手动选择时，有产物先显示产物列表，没有产物先显示资料库。

资料库 Tab
只显示已加入资料的轻量清单

每项只展示文件类型和文件名，不显示摘要、说明、路径或更新时间；窗口内保留“进入项目资料库”按钮。

文件树 Tab
替代当前对话资源里的 Wiki，可打开文件到画布

当前对话资源窗口不显示 Wiki，第二个入口改为项目文件树；单击文件在画布中打开，右键只显示“在画布中打开”和“添加到对话”。添加到对话等同现有插件里的 @ 文件引用。

技能 Tab
点击后加入输入，不直接执行

默认显示项目技能，可切换全局技能；每项只显示技能名和一句短用途。点击技能后作为 @ 技能加入当前输入，等待用户补充任务要求。

产物 Tab
当前对话产物清单，右键可沉淀或落到文件树

每项只显示文件类型和文件名；单击在画布中打开，右键包含在画布中打开、添加到对话、加入项目资料库、放入项目文件树。

@ 引用
发送后清空输入框，Turn 保留引用快照

添加到对话沿用现有插件的结构化 @ 引用：文件、技能和产物先进入输入框，发送时冻结为本轮显式引用；发送成功后输入框清空，不自动带到下一轮。用户消息可折叠显示“已添加引用 x 个”，FRIDAY 回复底部继续显示实际“参考文件 x 个”。

进入规则
生成可视产物自动切换，已有主产物自动恢复

用户也可以手动打开工作区里的已有可显示文件，一边看内容一边和 FRIDAY 对话。

对话历史
每个对话打开时加载完整历史

项目可以有多个对话；切换对话时，产物画布和右侧 FRIDAY 侧栏都随当前对话切换。

工作线侧栏
最左侧是常驻小侧边栏，项目打开第二层菜单

点击项目后显示全部项目；进入项目主页后，再开始新对话或点击已有对话进入对话页。

启动入口
首次选择或新建工作区，之后恢复上次工作区

工作区列表只作为切换器，默认第一屏直接进入工作台。

产品语气
FRIDAY 是加入项目的工作伙伴

初始化、识别和建议文案可以轻微拟人化，例如“让 FRIDAY 加入一个项目”“FRIDAY 已查看文件夹结构”，但行为说明必须保持清楚。

本地结构
工作区内使用可见的 FRIDAY/ 目录

项目根目录和现有文件树是直接信息来源；FRIDAY 自己产生和管理的内容放在 FRIDAY/。

混合工作区
不再创建 Knowledge/ 和 Code/ 作为默认分类目录

FRIDAY 只有一个混合工作区模型；已有文件通过 metadata 标记为资料、代码或两者兼具，不因为分类被移动或复制。

初始化
让 FRIDAY 加入项目后，才创建 FRIDAY/

加入项目不移动已有文件；如果这个文件夹本身就是资料库，用户可以让 FRIDAY 把现有文件登记为项目资料。

资料命名
产品侧叫项目资料库，技术侧仍可叫 context

资料默认可参与对话，但使用时按清单、说明、摘要、原文逐层披露。

加入资料库
从项目文件树加入，只登记资料身份

项目资料库是管理视图；文件成为资料时只登记相对路径、说明、摘要和启用状态，不为现有文件创建隐藏副本。

资料说明
导入后不弹必填表单，说明可以后补

FRIDAY 后台生成摘要和建议用途，但资料详情仍以原文件信息优先。

资料状态
新增资料默认启用，允许暂停

暂停资料仍保留在项目资料库，但 FRIDAY 默认不参考；用户可在对话中点名使用。

Agent 自由度
资料、Skill、产物都是显式文件，不做默认白名单限制

FRIDAY 可以自由判断和组合相关文件；用户点名或排除某项时，只作为当前任务指令。

参考披露
回答底部显示“参考文件 x 个”

点击后展开实际参考文件列表；默认折叠，不放在 FRIDAY 侧栏作为主要展示。

技能库
项目技能和全局技能无优先级

只区分范围和存储位置。Skill 由用户主动创建，创建后默认启用。

Git 同步
项目资料和项目技能是可共享资产，不是强制默认提交

FRIDAY/context/ 和项目 FRIDAY/skills/ 可以作为协作内容；是否进入 Git 由项目来源和 Git Profile 决定。

桌面端 v0 产品边界

必须跑通
独立 Desktop Host + 本地工作区 + 项目主页

用户可以启动桌面端，进入上次项目主页，切换项目，开始新对话或打开已有对话。

核心工作流
对话、过程 trace、产物画布必须形成闭环

右侧 FRIDAY 加载完整历史；过程、工具调用和参考文件可折叠披露；生成或打开可显示文件时进入产物画布。

资料与知识
项目资料库 v1 可用，项目 Wiki 暂缓

资料以项目文件树相对路径和 metadata 为事实来源；Wiki 先只保留项目主页占位入口。旧插件 Wiki 不成熟，只作为历史探索参考，不进入 v0 可用闭环。

协作边界
Git 同步采用 allowlist，而不是提交整个 FRIDAY/

第一轮只把 context、项目 skills 和最小 project manifest 视作可共享资产；会产生频繁冲突的 conversations、traces、state、runtime cache 和个人 UI 状态默认本地。

先占位
团队、总日历、项目日历、模块、Soul 高级配置先保留入口

这些能力进入总模块栏或项目主页，但 v0 不定义完整数据结构和复杂交互，避免第一轮产品边界失控。

暂不做
云账号、实时协作、完整 marketplace、移动端和自动升级

第一轮只证明 FRIDAY 可以作为本地优先桌面 Host 跑通核心工作台，不做完整组织协作平台。

验收口径
一个本地项目能完成完整泛文档任务

添加资料、开始对话、查看过程、生成或打开产物、引用文件、保存状态、下次恢复，这是 v0 的产品闭环。

落盘对象与同步分层

已确认原则：FRIDAY 的落盘对象先分成项目事实、运行过程和个人状态三层。v0 不把所有 FRIDAY/ 内容都当成协作数据；项目资料库和项目技能只是可共享资产层，是否进入 Git 由 Git Profile 决定。Reference 和 Trace 必须分开：同一个文件可能被用户 @、被 FRIDAY 读取、出现在回答底部，也可能只出现在过程 trace 里，每种状态代表不同产品含义。

Git Profile
项目来源决定共享层是否进入仓库

新建本地项目默认 local-only；已有 Git 文件夹不自动污染仓库；从远端拉取的项目如果已有 FRIDAY 共享层，则按 remote-managed 加载。

Project
项目 manifest 和个人状态分开保存

project.json 只保存 schema version、项目识别和共享层版本；当前打开对话、窗口布局和设备状态留在本地状态里。

Context
项目资料库是可共享资产

保存资料登记、说明、metadata、启用状态和产物入库记录；启用共享层后，它是团队通过 Git 协作时最稳定的事实层。

File Role
已有文件不自动挪动，只登记角色

知识资料、代码文件、兼具两者和排除项都通过 registry / metadata 表达；物理整理文件必须是单独确认后的操作。

Skill
项目技能可共享，全局技能属于本机

FRIDAY/skills/ 保存当前项目技能；全局 Skills 放在本机全局目录，不随单个项目默认同步。

Conversation / Turn
方案 B：索引、Turn 快照和 Trace 独立文件

每个对话目录下放 conversation.json、turns/<turnId>.json 和 traces/<turnId>.jsonl；对话索引用于快速恢复，Turn 保存稳定消息快照，Trace 只在展开过程时懒加载。

Artifact
方案 B：产物文件 + manifest 记录版本关系

FRIDAY/artifacts/<artifactId>/ 下保存 artifact.json 和 files/<versionId>/content.ext；当前对话产物列表读取 artifactId，画布打开 currentVersionId。

Import
项目外文件从 + 加入时默认复制快照

通过 + 添加的项目外文件或图片先复制到 FRIDAY/imports/<conversationId>/<importId>/，再作为当前输入引用；项目内文件只引用相对路径。每个 import 目录保存原文件快照和 import.json，imports/ 默认本地，不自动进入项目资料库。

Archive
对话不删除，只归档；imports 跟随对话整包移动

归档某个对话时，FRIDAY/conversations/<conversationId>/ 和 FRIDAY/imports/<conversationId>/ 一起转入 FRIDAY/archive/conversations/<conversationId>/。归档对话默认从活跃对话和最近对话隐藏，只能从项目主页的“查看归档对话”进入；打开时先只读，恢复后 conversationId 不变，按恢复时间回到活跃列表。

Artifact 归档
产物文件不随对话移动，只隐藏当前对话产物列表

FRIDAY/artifacts/ 下的产物文件可能被资料库、项目文件树或其它对话引用，因此归档对话时只保留 artifact 关联，不移动产物文件。恢复对话后，当前对话产物列表重新显示。

Artifact 状态
产物先属于对话，显式操作后才沉淀

@产物 引用 artifactId 和当时 versionId；加入项目资料库后回写 contextId，放入项目文件树后回写 projectTreePath。代码产物也先作为产物，用户确认后才成为项目真实文件。

已有文件画布
方案 B：轻量 Artifact wrapper，不复制原文件

项目文件树里的已有文件打开到画布时，只创建 wrapper 指向 projectTreePath，并记录 storageMode: project_file_reference。FRIDAY 修改时先生成草稿或 patch，用户确认后再写回真实文件。

权限模式
安全 / 标准 / 自主

标准是默认推荐模式：FRIDAY 产物自动保存到 FRIDAY/artifacts/；写入项目真实文件树前保留修改审查。安全模式更保守；自主模式对齐 Codex Full access，用户明确选择后，FRIDAY 可以完整访问本地文件、运行命令和使用网络，不再默认逐项确认。

权限范围
安全确认关键动作，标准保留真实文件审查，自主完整访问

安全：项目内读取和 FRIDAY 状态写入可以继续，真实文件、命令、网络、删除和模块变更每次确认。标准：项目内读取和产物自动保存，真实文件写回走 diff / patch，外部路径、命令、网络和高风险 Git 动作按风险确认。自主：按本机账号权限直接读写文件、访问项目外路径、运行命令、联网、执行 Git 和安装依赖；当前模式只在输入框底部显示，过程区继续保留 trace 和停止入口。

权限切换
v0 不做临时提权，只做当前对话级模式切换

输入框底部工具栏固定为“+ · 模型名称 · 当前权限模式”，例如“+ · 5.5 · 标准”。“+”承载添加文件、图片、Skill 和 @ 引用；权限文字点击后只切换安全 / 标准 / 自主。当前对话的切换不直接修改项目默认权限，新对话再继承项目默认值。用户从自主切回标准 / 安全时，如果 FRIDAY 正在执行工具或写文件，先停止后续排队动作，再选择停止当前任务或等当前步骤完成后切换。

Trace / Reference
过程 trace 和用户可见引用分开保存

Trace 记录工具调用、读写文件、命令执行、审批和失败状态；Reference 记录用户显式添加、发送时解析、最终回答披露的来源。二者都跟随 Turn 本地保存，但服务不同 UI。

Explicit
用户添加的是本轮显式引用

用户通过 @ 文件、@ 技能、@ 产物加入输入框的内容，发送前显示为 chip；发送后输入框清空，用户消息下方折叠显示“已添加引用 x 个”。

Resolved
发送时冻结成 Turn 的引用快照

FRIDAY 把结构化输入、mention resolver 结果和 context summary 绑定到本轮 Turn，用于历史恢复和调试；它不自动改变项目资料库。

Trace
实际读取和写入属于过程事实

FRIDAY 执行中读取、搜索、写入、运行命令、审批或失败重试都进入 Trace；右侧过程区按需展示，历史恢复时懒加载。

Answer Ref
方案 B：候选来源池 + 受限筛选

“参考文件 x 个”来自 Answer Reference。它先从用户 @ 引用、FRIDAY 实际读取文件、当前产物和选区中形成候选池，再筛出真正支撑本轮回答的来源。

落盘快照
AnswerReference 随 Assistant Turn 固化

必须保存 targetType、targetUri、displayName、fileKind、primarySourceType、sourceTypes、order 和 createdAt；traceIds、explicitReferenceIds、artifactId、selectionId 作为可选证据链。

展开字段
只显示文件类型、文件名和来源类型

展开后使用 @引用、FRIDAY 读取、当前产物、选区四类来源标签；默认不显示完整路径，点击文件在画布中打开，悬停或右键再提供路径、定位和加入资料库动作。

筛选排除
参考文件不是工具 trace 或模块列表

Skill、模块、工具本身、失败重试、审批、系统 prompt、权限检查、路径探测、目录枚举和只写入但未支撑回答的文件，都不进入回答底部。

Workspace State
窗口、画布和折叠状态是个人状态

保存当前打开对话、布局、标签、折叠状态和设备状态；不进入 Git 协作层。

目录草案：项目根目录和现有文件树是直接信息来源；FRIDAY/project.json、FRIDAY/context/、FRIDAY/skills/ 属于可共享资产层；FRIDAY/context/ 是资料登记层，项目文件记录相对路径和文件角色，不复制现有文件；FRIDAY/imports/<conversationId>/<importId>/ 保存通过 + 添加的项目外文件快照和 import.json，默认本地；对话不做删除，只做归档，归档时 FRIDAY/conversations/<conversationId>/ 与 FRIDAY/imports/<conversationId>/ 一起转入 FRIDAY/archive/conversations/<conversationId>/；FRIDAY/artifacts/<artifactId>/artifact.json 记录产物 manifest，files/ 保存关键版本文件；FRIDAY/conversations/<conversationId>/conversation.json 保存对话索引，turns/ 保存单轮快照，traces/ 保存过程事件流；FRIDAY/state/、FRIDAY/runtime/、FRIDAY/local/ 默认本地。

v0 核心工作流状态流

1. 项目主页接收意图

用户进入上次项目主页，在输入框里说明要做什么，或点击已有对话继续工作。

2. 创建或恢复对话

FRIDAY 根据输入创建新对话；打开旧对话时加载完整历史，并恢复该对话绑定的主产物状态。

3. FRIDAY 运行并披露过程

右侧 FRIDAY 区域显示完整对话、过程 trace、工具调用、确认事项和继续输入，过程卡片可以折叠。

4. 生成或打开产物

当 FRIDAY 生成 Markdown、HTML、报告等可显示文件，或用户手动打开已有可显示文件时，进入产物状态。

5. 产物画布接管主区域

主区域从对话工作台切换为产物画布；右侧仍是同一对话的完整 FRIDAY 历史和过程。

6. 引用披露和状态恢复

回答底部显示“参考文件 x 个”；对话、产物、trace 和引用记录落盘，下次打开项目时可恢复。

最高优先级

Desktop HostAdapter contract。它决定 runtime、文件系统、权限、Git、trace 和 UI 的边界。

核心体验

ArtifactStore、产物画布、项目资料库 metadata、Reference / Trace UI contract。

M2 技术栈决策

v0 选择 Electron-first。M11 前先验证 BrowserWindow、preload bridge、renderer 隔离和 HostAdapter IPC。

Desktop HostAdapter Contract

这不是 Electron / Tauri API，也不是 UI 组件。它是 FRIDAY Runtime 和桌面端真实环境之间的能力合同：Runtime 只提出请求，Desktop HostAdapter 负责权限、执行、trace 和状态落盘。

Runtime 不直接碰系统

不直接读写文件、不直接跑命令、不直接操作 Git、不直接控制窗口。所有真实动作都走 host。

Host 执行真实动作

桌面端负责路径解析、权限检查、文件读写、工具执行、产物打开、状态保存和 UI 事件派发。

权限和 trace 是硬边界

安全 / 标准 / 自主三档由 HostAdapter 执行；读取、写入、命令、审批、失败都进入 trace。

先定义合同再选壳

Electron / Tauri 的选择要服务于这些 host 能力，而不是先选技术栈再反推能力。

草案接口 用途 备注
getActiveProject()返回当前项目和基本状态。项目主页和 runtime 启动前都需要。
resolveProjectPath(pathIntent)把 runtime 的路径意图解析为项目内、FRIDAY 内或外部路径。权限判断前置。
readProjectFile(path) / writeProjectFile(path)读写项目真实文件。写入必须进入权限和 trace。
createImport(file)把项目外文件复制为当前对话快照。默认进入 FRIDAY/imports。
createArtifact(payload) / openArtifact(id)创建、打开、恢复产物。连接 ArtifactStore 和画布。
registerContextItem(payload)把文件、导入或产物登记为项目资料。写入 FRIDAY/context。
getPermissionSnapshot(conversationId)冻结当前对话权限模式。随 Turn 保存。
requestApproval(action)向 UI 请求确认、拒绝或停止。安全 / 标准模式需要。
executeTool(invocation)执行命令、Git 或工具。Host 统一落 trace。
emitTrace(event)向过程区发送事件。不等同回答底部参考文件。
persistTurn(turn)保存当前轮消息、引用和结果。Conversation 恢复依赖它。
archiveConversation(id) / restoreConversation(id)归档和恢复对话包。imports 随 conversationId 一起移动。
