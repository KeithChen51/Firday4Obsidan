产品定位
FRIDAY Desktop 是本地优先的工作台

面向组织和团队里的泛文档工作者，不把产品表达成 Coding Agent。

形态原则
桌面端是新形态，但不偏离 FRIDAY 既有能力

交互可以脱离 Obsidian 重新组织；能力侧优先复用 runtime、过程面板、资料、Skill、Soul、同步和本地状态。

视觉基准
Codex 只参考信息结构，视觉回到 FRIDAY VI

不是机械套色，而是遵守柔和墨色、Warm Bone 文档底色、少量 Muted Teal 功能色、少阴影和低侵入排版。

产物画布
默认一个当前产物，顶部标签切换

需要并行查看时，用户拖拽标签把产物拆成左右或上下并列显示。

进入规则
生成可视产物自动切换，已有主产物自动恢复

用户也可以手动打开工作区里的已有可显示文件，一边看内容一边和 FRIDAY 对话。

对话历史
每个对话打开时加载完整历史

项目可以有多个对话；切换对话时，产物画布和右侧 FRIDAY 侧栏都随当前对话切换。

工作线侧栏
最左侧是常驻小侧边栏，项目打开第二层菜单

点击项目后显示全部项目；进入项目主页后，再开始新对话或点击已有对话进入对话页。

启动入口
首次选择或新建工作区，之后恢复上次工作区

工作区列表只作为切换器，默认第一屏直接进入工作台。

产品语气
FRIDAY 是加入项目的工作伙伴

初始化、识别和建议文案可以轻微拟人化，例如“让 FRIDAY 加入一个项目”“FRIDAY 已查看文件夹结构”，但行为说明必须保持清楚。

本地结构
工作区内使用可见的 FRIDAY/ 目录

项目根目录和现有文件树是直接信息来源；FRIDAY 自己产生和管理的内容放在 FRIDAY/。

混合工作区
不再创建 Knowledge/ 和 Code/ 作为默认分类目录

FRIDAY 只有一个混合工作区模型；已有文件通过 metadata 标记为资料、代码或两者兼具，不因为分类被移动或复制。

初始化
让 FRIDAY 加入项目后，才创建 FRIDAY/

加入项目不移动已有文件；如果这个文件夹本身就是资料库，用户可以让 FRIDAY 把现有文件登记为项目资料。

资料命名
产品侧叫项目资料库，技术侧仍可叫 context

资料默认可参与对话，但使用时按清单、说明、摘要、原文逐层披露。

加入资料库
从项目文件树加入，只登记资料身份

项目资料库是管理视图；文件成为资料时只登记相对路径、说明、摘要和启用状态，不为现有文件创建隐藏副本。

资料说明
导入后不弹必填表单，说明可以后补

FRIDAY 后台生成摘要和建议用途，但资料详情仍以原文件信息优先。

资料状态
新增资料默认启用，允许暂停

暂停资料仍保留在项目资料库，但 FRIDAY 默认不参考；用户可在对话中点名使用。

Agent 自由度
资料、Skill、产物都是显式文件，不做默认白名单限制

FRIDAY 可以自由判断和组合相关文件；用户点名或排除某项时，只作为当前任务指令。

参考披露
回答底部显示“参考文件 x 个”

点击后展开实际参考文件列表；默认折叠，不放在 FRIDAY 侧栏作为主要展示。

技能库
项目技能和全局技能无优先级

只区分范围和存储位置。Skill 由用户主动创建，创建后默认启用。

Git 同步
项目资料和项目技能是可共享资产，不是强制默认提交

FRIDAY/context/ 和项目 FRIDAY/skills/ 可以作为协作内容；是否进入 Git 由项目来源和 Git Profile 决定。

桌面端 v0 产品边界

必须跑通
独立 Desktop Host + 本地工作区 + 项目主页

用户可以启动桌面端，进入上次项目主页，切换项目，开始新对话或打开已有对话。

核心工作流
对话、过程 trace、产物画布必须形成闭环

右侧 FRIDAY 加载完整历史；过程、工具调用和参考文件可折叠披露；生成或打开可显示文件时进入产物画布。

资料与知识
项目资料库 v1 可用，项目 Wiki 先做摘要和详情入口

资料以项目文件树相对路径和 metadata 为事实来源；Wiki 先承载知识图谱预览和详情页，不要求完整自动生成能力。

协作边界
Git 同步采用 allowlist，而不是提交整个 FRIDAY/

第一轮只把 context、项目 skills 和最小 project manifest 视作可共享资产；会产生频繁冲突的 conversations、traces、state、runtime cache 和个人 UI 状态默认本地。

先占位
团队、总日历、项目日历、模块、Soul 高级配置先保留入口

这些能力进入总模块栏或项目主页，但 v0 不定义完整数据结构和复杂交互，避免第一轮产品边界失控。

暂不做
云账号、实时协作、完整 marketplace、移动端和自动升级

第一轮只证明 FRIDAY 可以作为本地优先桌面 Host 跑通核心工作台，不做完整组织协作平台。

验收口径
一个本地项目能完成完整泛文档任务

添加资料、开始对话、查看过程、生成或打开产物、引用文件、保存状态、下次恢复，这是 v0 的产品闭环。

落盘对象与同步分层

已确认原则：FRIDAY 的落盘对象先分成项目事实、运行过程和个人状态三层。v0 不把所有 FRIDAY/ 内容都当成协作数据；项目资料库和项目技能只是可共享资产层，是否进入 Git 由 Git Profile 决定。

Git Profile
项目来源决定共享层是否进入仓库

新建本地项目默认 local-only；已有 Git 文件夹不自动污染仓库；从远端拉取的项目如果已有 FRIDAY 共享层，则按 remote-managed 加载。

Project
项目 manifest 和个人状态分开保存

project.json 只保存 schema version、项目识别和共享层版本；当前打开对话、窗口布局和设备状态留在本地状态里。

Context
项目资料库是可共享资产

保存资料登记、说明、metadata、启用状态和产物入库记录；启用共享层后，它是团队通过 Git 协作时最稳定的事实层。

File Role
已有文件不自动挪动，只登记角色

知识资料、代码文件、兼具两者和排除项都通过 registry / metadata 表达；物理整理文件必须是单独确认后的操作。

Skill
项目技能可共享，全局技能属于本机

FRIDAY/skills/ 保存当前项目技能；全局 Skills 放在本机全局目录，不随单个项目默认同步。

Conversation / Turn
对话和单轮消息默认本地

保存标题、完整历史、用户输入、FRIDAY 回复和确认事项；v0 不作为多人 Git 协作事实来源。

Artifact
产物放在 FRIDAY/artifacts/，加入资料库时再决定去向

生成的 md、html、report 等文件可以在画布中打开；用户可把产物放入 FRIDAY 托管资料文件夹，或写入项目文件树指定位置。

Trace / Reference
过程和引用记录跟随对话本地保存

Trace 记录工具调用、读写文件和 runtime event；Reference 记录某次回答实际参考文件，默认只服务恢复和追溯。

Workspace State
窗口、画布和折叠状态是个人状态

保存当前打开对话、布局、标签、折叠状态和设备状态；不进入 Git 协作层。

目录草案：项目根目录和现有文件树是直接信息来源；FRIDAY/project.json、FRIDAY/context/、FRIDAY/skills/ 属于可共享资产层；FRIDAY/context/ 是资料登记层，项目文件记录相对路径和文件角色，不复制现有文件；FRIDAY/artifacts/ 是产物区，产物可被加入资料库或写入项目文件树；FRIDAY/conversations/、FRIDAY/traces/、FRIDAY/references/、FRIDAY/state/、FRIDAY/runtime/、FRIDAY/local/ 默认本地。

v0 核心工作流状态流

1. 项目主页接收意图

用户进入上次项目主页，在输入框里说明要做什么，或点击已有对话继续工作。

2. 创建或恢复对话

FRIDAY 根据输入创建新对话；打开旧对话时加载完整历史，并恢复该对话绑定的主产物状态。

3. FRIDAY 运行并披露过程

右侧 FRIDAY 区域显示完整对话、过程 trace、工具调用、确认事项和继续输入，过程卡片可以折叠。

4. 生成或打开产物

当 FRIDAY 生成 Markdown、HTML、报告等可显示文件，或用户手动打开已有可显示文件时，进入产物状态。

5. 产物画布接管主区域

主区域从对话工作台切换为产物画布；右侧仍是同一对话的完整 FRIDAY 历史和过程。

6. 引用披露和状态恢复

回答底部显示“参考文件 x 个”；对话、产物、trace 和引用记录落盘，下次打开项目时可恢复。

桌面端信息层级定稿预览

下一步讨论：既有能力映射

对话与过程

把现有 runtime progress、tool trace 和过程折叠抽成桌面端中间对话区能力。

工作区边界

把项目路径、权限、Git 同步和文件修改审查放进 Desktop HostAdapter。

项目资料库

承接 context、mention、memory、摘要和回答底部的实际参考文件披露。

产物

承接 FRIDAY 生成文件、用户已有可显示文件和修改结果；默认单主产物，顶部标签切换，拖拽标签后可并列。

技能与 Soul

把项目 Skill、全局 Skill、Soul 行为画像和未来模块组合放到独立管理入口。

PI 与模块

把 PI SDK 和社区能力映射成 FRIDAY 可审查、可启用、可本地修改的模块协议。

工作区启动流程

项目页入口

用户在项目页点击“让 FRIDAY 加入一个项目”。

选择项目位置

用户可以新建文件夹，也可以选择一个已有文件夹。

FRIDAY 先观察

如果是已有文件夹，FRIDAY 先只读查看文件夹结构，再给出初步结论。

确认加入

用户可以加入项目或取消；项目资料库视图进入项目后再定义。

再次打开

恢复上次项目主页，最左侧保留项目切换入口。
